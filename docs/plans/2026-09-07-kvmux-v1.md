# KVMux v1 implementation plan

## Outcome and scope

Build the local USB KVM specified by
`docs/design/kvm-technical-design-v1.md`: one native capture source, one CH9329
serial link, one SDL3/ImGui/OpenGL window, fresh-frame video, and explicit safe
input capture/release on Windows 11, Ubuntu 24.04, and macOS 14+.

Excluded features remain those in section 1 of the design. Hardware acceptance,
latency claims, signing, and notarization require real evidence and cannot be
completed with simulated devices. Existing changes: none. Authorization:
implementation. The user's dependency instruction supersedes the design's
vcpkg-manifest choice.

## Decisions and constraints

- Build with C++20, CMake Presets, Ninja, and CTest. Configuration never downloads
  dependencies. Small and source-oriented dependencies are pinned in
  `third_party/` with their licenses. FFmpeg is discovered as a system/runtime
  dependency. libserialport will be vendored if its portable build can be kept
  focused; otherwise it is an explicit discovered dependency.
- `kvmux_core` is a UI-free static library. Only `CaptureSource` and
  `ControlSink` are interfaces. Platform code owns native objects and publishes
  application-owned samples.
- Video uses capacity-one `LatestValue<T>` mailboxes. Control uses a 128-event
  ordered queue, epoch invalidation, limited adjacent motion coalescing, and an
  independent emergency release request.
- CH9329 framing is bounded to LEN <= 64. One transaction is in flight. Relative
  movement and wheel transactions are never replayed after an uncertain ACK.
- The main thread owns SDL, ImGui, and OpenGL. Capture, video, and serial work are
  stoppable and joinable. No worker calls UI code.
- macOS is the current development host. Cross-platform compile and hardware
  claims remain unverified until the corresponding environment is available.

### T2: CH9329 protocol and safe control core

Status: in_progress
Depends on: T1
Acceptance: A2, A3
Files: create `src/control/` codec, parser, HID state, control event/queue,
libserialport-backed serial worker, fake serial transport, and focused tests.
Codec consumes/spans bytes and returns owned bounded frames; queue submission
returns accepted/not-ready/overloaded and release is separate. The serial worker
owns the port, permits one transaction in flight, validates ACKs, applies the
100 ms stall and 500 ms hard timeout rules, polls GET_INFO only while idle, and
performs the common bounded ReleaseAll sequence.

Check: build and run `ctest --preset dev -R "ch9329|control"`; protocol vectors,
fragment/noise cases, six-key admission, coalescing, epochs and overload pass.
Commit: `feat(control): add CH9329 protocol and ordered input core`.

Evidence: software portion passes in Debug: codec/parser, queue, HID state and
the libserialport-backed single-transaction worker. The design-required fake
transport check covers partial writes, handshake/config validation, initial
ReleaseAll, 100/500 ms timeout recovery, epoch invalidation and no replay of
uncertain relative motion. Real CH9329 behavior remains unverified, so P1/T2
remains in progress.

## Final acceptance

On each target platform, configure/build/test with its documented Ninja preset,
launch `kvmux`, select the actual capture and serial devices, verify preview,
absolute/relative input, Host-key release, focus-loss release, stale-video
release, reconnect-to-Preview, fullscreen, and ordered shutdown. Complete the
hardware and performance tables using real measurements only.
