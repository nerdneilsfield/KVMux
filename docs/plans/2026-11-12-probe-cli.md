# 硬件自检 CLI：实施计划

Plan readiness: ready（用户 2026-11-12 要求：先把功能全部实现，提供一个 CLI，用户在 macOS 上运行它来测试各项功能）。

## 目标与范围

在 `kvmux-relay` 里加两个自检子命令，让用户不开 GUI 也能在真实硬件上验证：

- CH341 libusb 后端与系统串口上的 CH9329（`docs/plans/2026-11-12-ch341-usb-backend.md` 的 B3–B6）；
- 分离 relay 的 control 角色与 video 角色（`docs/plans/2026-11-12-split-relay-roles.md` 的拓扑）。

放在 `kvmux-relay` 而不是新程序：它已是 headless 程序、已有 `--list-serial` 和参数解析，三个平台都构建。不新增可执行文件。

不做：GUI 自检、视频画质或延迟测量（AGENTS 要求不能把内部时间戳当成 KVM 性能）、自动化的硬件 CI。

## 设计

两个命令都只通过现有的生产接口工作，不绕开它们：控制走 `ControlSink`（本地 `Ch9329ControlSink` 或 relay 的 `NetworkControlSink`），视频走 `CaptureSource`（`NetworkCaptureSource`）。所以自检通过就说明 GUI 用的同一条路径可用。

### `--probe-control`

```
kvmux-relay --probe-control (--serial PORT [--baud 9600] | --relay HOST [--control-port 17000])
            [--keys] [--mouse] [--timeout-ms 5000]
```

步骤依次执行，每步打印一行 `PASS` / `FAIL` / `SKIP` 和原因；任一步 FAIL 后执行释放并停止：

1. **open**：`--serial` 时打印解析出的后端（`ch341-usb` 或系统串口）；`connect` 后等待状态离开 disconnected。失败时打印 `ControlSnapshot::error`（即 CH341 计划里的具体原因：被驱动占用、权限、WinUSB、波特率不支持）。
2. **ready**：在超时内等到 `ready` 且 `usb_ready`，打印 CH9329 握手结果。`--relay` 时客户端角色为 control。control relay 要求客户端声明画面新鲜，CLI 没有画面，所以这一步之前它通过 `video_presented` 以 30 Hz 递增序号报告展示，并在输出里明确写出"无画面，CLI 自行声明新鲜，仅用于自检"。这条路径只存在于自检命令里，不进入 GUI。
3. **keys**（仅 `--keys`）：按下并松开左 Shift 一次（不会在目标上输入字符），等待 ACK。
4. **mouse**（仅 `--mouse`）：相对移动右 20 像素、再左 20 像素，等待 ACK。
5. **release**：`release_all`，在超时内等到 `release_confirmed`；之后 `disconnect`。
6. **unplug**（手动，仅提示）：结尾打印"如需测试拔出：重新运行并在 ready 后拔掉设备"。运行中设备消失时，命令应打印状态变为故障且 `release_confirmed=false`，退出码非零。

不加 `--keys` / `--mouse` 时不向目标发送任何输入，只验证打开、握手和释放。

退出码：全部 PASS 为 0；任一步 FAIL 为 1；参数错误为 2（与现有一致）。

### `--probe-video`

```
kvmux-relay --probe-video HOST [--control-port 17000] [--video-port 17001] [--seconds 5]
```

以 video 角色连接，打印握手结果（含 `role_unsupported`）、codec、分辨率，在指定时长内统计收到并解码的帧数和最长帧间隔，超过 10 秒的时长用来验证保活不掉线。只报告计数，不作为延迟或性能结论。

### 输出示例格式

```
[PASS] open     backend=ch341-usb port=ch341-usb:20-1 baud=9600
[PASS] ready    usb=ready version=0x30
[SKIP] keys     (pass --keys to send Left Shift)
[PASS] release  confirmed in 12 ms
```

CH341 版本字节由后端在打开时以 info 级别日志输出，CLI 在 `--serial ch341-usb:...` 时读取并打印（若不方便传递，至少在 `--debug` 日志中可见）。

## 验收

| ID | 行为 | 检查与预期 |
| --- | --- | --- |
| P1 | 参数 | `--probe-control` 同时给 `--serial` 和 `--relay`、或都不给：退出码 2 |
| P2 | 串口失败路径 | 本机：`--probe-control --serial /dev/does-not-exist` 打印 FAIL open 和原因，退出码 1；`--serial ch341-usb:9-9` 打印设备不存在 |
| P3 | relay control 路径 | 本机：FakeSerial 不可用于独立进程，所以用 CTest 启动 control relay（复用 `relay_role_test` 的启动方式）并运行 `--probe-control --relay 127.0.0.1 --keys --mouse`，退出码 0，各步 PASS |
| P4 | relay video 路径 | CTest 以 FakeCapture 启动 video relay，`--probe-video 127.0.0.1 --seconds 11`，帧数大于 0，退出码 0；对 control relay 运行时打印角色不匹配，退出码 1 |
| P5 | 硬件 | 用户在 macOS 上对 `ch341-usb:` 设备运行 `--probe-control --keys --mouse`；结果记入 `docs/hardware-validation.md`。未运行前标为未验证 |

P3/P4 若需要独立进程中的假设备，在现有测试夹具允许的范围内实现；不行就把 P3/P4 改为在测试进程内调用同一个自检函数（命令解析与自检逻辑分开，自检函数接收 `ControlSink&` / `CaptureSource&`）。
